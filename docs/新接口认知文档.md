## 二、鉴权方案（PASSWORD 模式，前端直连）

```
登录页输入工号+口令
  → 前端生成 timestamp/nonce，HMAC-SHA256 签名
  → 口令 RSA 公钥加密（Base64）
  → POST /api/open/auth/token 换 JWT
  → 业务接口带 Authorization: Bearer {token}
```

| 要素 | 值/规则 |
|---|---|
| appKey | `fjut-eva` |
| appSecret | 管理员提供（不记录在文档中），配置于 `src/config/openApi.js` 的 `APP_SECRET`。曾因密钥值错误报"签名校验失败"，2026-11-09 更正后登录打通 |
| 签名串 | `appKey + "\n" + username + "\n" + timestamp + "\n" + nonce`（四段、换行分隔、顺序固定） |
| 签名算法 | `HMAC-SHA256(key=appSecret, data=签名串)`，输出十六进制小写 |
| timestamp | 毫秒级，与服务器偏差 ≤ 300 秒 |
| nonce | 16~32 位随机串，同 appKey 下 10 分钟内不可重复 |
| 口令加密 | RSA 公钥加密（公钥在文档中给出）后 Base64，需管理员开启 `eva.open.password-login: true` |
| 令牌有效期 | 开发 4 小时 / 生产 2 小时，用户有操作时服务端自动续期 |
| 单点登录 | 令牌与 Web 端不互踢（已确认） |

### 安全提示

appSecret 打包进前端 JS 后对任何使用者可见（devtools 可读），此方案为用户明确选择（方案 B）。若后续安全要求提高，应迁移到服务端签名（BFF）模式。

## 三、接口清单（7 个）

| 方法 | 接口地址 | 功能 |
|---|---|---|
| POST | `/api/open/auth/token` | 换取令牌（PASSWORD 模式，重复提交同 (taskId,objectUserId) 返回 400+ALREADY_SUBMITTED 见 4.5） |
| DELETE | `/api/open/auth/token` | 注销令牌（无响应体，令牌立即失效） |
| GET | `/api/open/eva/vote/tasks` | 我的测评任务列表 |
| GET | `/api/open/eva/vote/{taskId}/progress` | 我的测评进度（非参评人返回全 0，不返回 403） |
| GET | `/api/open/eva/vote/{taskId}/objects` | 待测评对象列表 |
| GET | `/api/open/eva/vote/{taskId}/objects/{objectUserId}` | 测评详情（对象信息+述职报告+题目+已作答回显） |
| POST | `/api/open/eva/vote/submit` | 提交测评答卷（201 返回最新进度） |

### 关键数据结构

- **任务**：`taskId / taskName / schoolYear / status(1已发布 2进行中 3已结束 4已封存) / statusText / submittable`
- **进度**：`totalCount / finishedCount / evalStatus(0未开始 1进行中 2已完成) / percent / submitTime`
- **对象**：`objectUserId / objectNo / objectName / objectDeptName / status(0待测评 1已提交 2已作废) / reportUrl(相对路径，拼服务地址访问，无需令牌) / partyEval(是否附带述责述廉评议表)`
- **题目**：`questionId / title / questionType(1单选必答 3文本选填) / required / options[{optionId, content}]`
- **已作答回显**：`submitted / selectedOptions(键为字符串题目ID，值选项ID数组) / textAnswers(键为字符串题目ID)`
- **提交体**：`taskId / objectUserId / submitToken(幂等，进页生成一次，重试复用) / items[{questionId, optionIds:[单个选项] 或 textAnswer}]`
- **党员评议表**：`partyEval=true 且 partyQuestions 非空` 时与常规题目一起展示、一起提交（作答只留痕不计分）

## 四、错误处理约定（与旧接口完全不同）

- 成功响应**无业务码包装**，直接返回数据体
- 错误通过 HTTP 状态码 + `{ status, code, message, timestamp }` 表达，`message` 可直接 Toast 展示
- `401`：令牌失效 → 拦截器自动 `dispatch('user/logout', { callApi: false })` 清登录态回登录页
- `400 + ALREADY_SUBMITTED`：重复提交，**前端视为已成功**（处理网络超时重试场景）
- 其他 `400`（TASK_NOT_PUBLISHED / TASK_NOT_START / TASK_EXPIRED / TASK_CLOSED 等）：读 `message` 提示
- 网络异常 / 超时：Toast 提示，同旧约定

### 考评页要点（views/evaluation/index.vue）

- 逐对象拉取详情（旧版是整卷共用一份模板）
- 党员评议表（partyQuestions）与常规题目分组展示、合并提交
- `submitted=true` 只读回显已作答，隐藏提交按钮
- 幂等：`submitToken` 进入页面生成一次，所有对象提交复用
- 提交成功：用 201 返回的最新进度刷新头部计数，并静默刷新对象列表状态
- 述职报告：`reportUrl` 拼 `VUE_APP_BASE_URL` 后 `window.open` 打开 PDF（替换旧版图片预览）
- 提交前校验：`submittable=false` 拦截；必答单选未作答拦截；文本题有内容才提交

## 七、注意事项（文档原文摘录）

1. 不要缓存业务数据（任务/对象/题目可能被管理员调整），每次进页重新拉取（代码已遵循）
2. 收到 `ALREADY_SUBMITTED` 不必再提交
3. 服务端未单独限流，建议指数退避、最多重试 3 次（当前代码未做自动重试）
4. 日志脱敏：勿输出完整 appSecret 与 token
5. 新增字段不影响解析；删除/改名字段会提前一个版本通知
