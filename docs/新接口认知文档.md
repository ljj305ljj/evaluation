## 二、鉴权方案（PASSWORD 模式，前端直连）

```
登录页输入工号+口令
  → 前端生成 timestamp/nonce，HMAC-SHA256 签名
  → 口令 RSA 公钥加密（Base64）
  → POST /api/open/auth/token 换 JWT
  → 业务接口带 Authorization: Bearer {token}
```

| 要素 | 值/规则 |
|---|---|
| appKey | `fjut-eva` |
| appSecret | 管理员提供（不记录在文档中），配置于 `src/config/openApi.js` 的 `APP_SECRET`。曾因密钥值错误报"签名校验失败"，2026-11-09 更正后登录打通 |
| 签名串 | `appKey + "\n" + username + "\n" + timestamp + "\n" + nonce`（四段、换行分隔、顺序固定） |
| 签名算法 | `HMAC-SHA256(key=appSecret, data=签名串)`，输出十六进制小写 |
| timestamp | 毫秒级，与服务器偏差 ≤ 300 秒 |
| nonce | 16~32 位随机串，同 appKey 下 10 分钟内不可重复 |
| 口令加密 | RSA 公钥加密（公钥在文档中给出）后 Base64，需管理员开启 `eva.open.password-login: true` |
| 令牌有效期 | 开发 4 小时 / 生产 2 小时，用户有操作时服务端自动续期 |
| 单点登录 | 取决于服务端 `single-login` 配置（v1.5 文档：同账号 Web 端登录可能使旧令牌失效，并行使用前与管理员确认；此前已确认为不互踢） |

### 安全提示

appSecret 打包进前端 JS 后对任何使用者可见（devtools 可读），此方案为用户明确选择（方案 B）。若后续安全要求提高，应迁移到服务端签名（BFF）模式。

### 关键数据结构

- **令牌响应（3.3/3.4）**：`token / tokenType / expiresIn / userId / username(工号) / nickName / deptName`；
  v1.4 起新增 `postRoleCode / postRoleName`（岗位角色，未建档为 null）、
  `deptCategory / deptCategoryName`（部门类别）、`roles`（系统角色，勿用于推断考评权限）；
  v1.5 起新增 `deptAdmin`（是否部门管理员：true 是 / false 否 / null 未建档）
- **任务**：`taskId / taskName / schoolYear / status(1已发布 2进行中 3已结束 4已封存) / statusText / submittable`
- **进度**：`totalCount / finishedCount / evalStatus(0未开始 1进行中 2已完成) / percent / submitTime`；
  v1.3 起新增 `excellentCount`（已评优秀数）/ `excellentLimit`（优秀上限，应评×2/3 向下取整，null 不受限，仅教职工有限制）
- **对象**：`objectUserId / objectNo / objectName / objectDeptName / jobDescription(职位描述，v1.1) / status(0待测评 1已提交 2已作废) / reportFileName / reportUrl(可能是绝对地址，需 `startsWith('http')` 判断是否拼服务地址，无需令牌) / partyEval(是否附带述责述廉评议表)`
- **题目**：`questionId / title / questionType(1单选必答 3文本选填) / required / questionCategory / options[{optionId, content}]`
- **已作答回显**：`submitted / selectedOptions(键为字符串题目ID，值选项ID数组) / textAnswers(键为字符串题目ID)`
- **提交体**：`taskId / objectUserId / submitToken(幂等，进页生成一次，重试复用) / items[{questionId, optionIds:[单个选项] 或 textAnswer}]`
- **党员评议表**：`partyEval=true 且 partyQuestions 非空` 时与常规题目一起展示、一起提交（按考评对象当前档案实时判定，作答只留痕不计分）
- **部门进度（4.6，v1.5）**：
  `taskId / deptId / deptName / raterCount(本部门其他参评人数) / finishedRaterCount / inProgressRaterCount / notStartedRaterCount / finishedPercent(按人数计) / raters[]`；
  `raters[]` 元素：`userId / username(工号) / nickName / deptName / postRoleCode / postRoleName / totalCount(该人应评对象数) / finishedCount / percent / evalStatus(0未开始 1进行中 2已完成) / evalStatusText / submitTime`；
  **始终排除调用者本人**；部门内无其他参评人时返回 `raterCount=0、raters=[]` 而非 404；不返回任何评定内容（选项/分值/等次）

## 四、错误处理约定（与旧接口完全不同）

- 成功响应**无业务码包装**，直接返回数据体
- 错误通过 HTTP 状态码 + `{ status, code, message, timestamp }` 表达，`message` 可直接 Toast 展示
- `401`：令牌失效 → 拦截器自动 `dispatch('user/logout', { callApi: false })` 清登录态回登录页
- `400 + ALREADY_SUBMITTED`：重复提交，**前端视为已成功**（处理网络超时重试场景）
- `400 + EXCELLENT_LIMIT_EXCEEDED`（v1.3）：评定"优秀"超过应评 2/3（接口文档标注仅教职工，前端已对所有角色按 2/3 前端拦截，总测评人数 1 人时不限制）；收到该码表示未落库，让用户改选后重新提交
- `400 + DEPT_ADMIN_REQUIRED`（v1.5）：调用 4.6 部门进度接口但当前账号不是部门管理员；前端用 `deptAdmin !== true` 提前隐藏入口，避免无谓请求
- 其他 `400`（TASK_NOT_PUBLISHED / TASK_NOT_START / TASK_EXPIRED / TASK_CLOSED 等）：读 `message` 提示
- 网络异常 / 超时：Toast 提示，同旧约定
- **silent 请求**：请求配置 `silent: true` 时，失败不弹 Toast、401 也不触发自动登出（用于退出登录时注销令牌——令牌已过期时该接口返回 401「登录状态已过期」属预期，不应提示用户）。目前仅 `deleteToken` 使用

### 考评页要点（views/evaluation/index.vue）

- 逐对象拉取详情（旧版是整卷共用一份模板）
- 党员评议表（partyQuestions）与常规题目分组展示、合并提交
- `submitted=true` 只读回显已作答，隐藏提交按钮
- 幂等：`submitToken` 进入页面生成一次，所有对象提交复用
- 提交成功：用 201 返回的最新进度刷新头部计数，并静默刷新对象列表状态
- 述职报告：`reportUrl` 直接作为图片预览地址使用（当前服务端已返回完整地址；接口文档建议的 `startsWith('http')` 兼容相对路径写法暂未实现，若服务端改回相对路径需补拼 `VUE_APP_BASE_URL`）
- 头部展示：应考评/已考评人数 + 已评优秀人数（`excellentCount`，红色数字）；总测评人数 > 1 时所有人都会显示规则提醒"优秀不超过总测评人数2/3，当前剩余可评优秀 N 人"（剩余人数加粗）
- 优秀比例：**不看岗位角色，所有人统一按"总测评人数×2/3 向下取整"限制；总测评人数只有 1 人时不限制**（`excellentLimit` 计算属性：总人数 ≤1 返回 null 不限制；服务端下发了 `excellentLimit` 就用服务端值，未下发则前端自行按 2/3 计算）；收到 `EXCELLENT_LIMIT_EXCEEDED` 表示未落库，改选后重新提交
  - 注意：接口文档 v1.3 只写"教职工"受此限制，前端已按需求放开到全部角色；服务端是否也对全部角色校验需与后端确认
  - 名额用尽时：仅主考核测评表（非 partyQuestions）的"总体评价"题禁选"优秀"（`isExcellentDisabled`）
- 顺序测评锁：对象按列表顺序，未提交中只有第一个可作答，后续对象加锁（点击提示，不置灰）；已作废（status=2）对象隐藏且不阻断顺序
- 提交前校验：`submittable=false` 拦截；必答单选未作答拦截；文本题有内容才提交

### 部门管理员进度（views/home/index.vue，v1.5）

- 判据：换令牌响应 `deptAdmin === true`（存于 `userInfo.deptAdmin`）；`false`/`null` 均不展示入口，不发请求
